Pulling more sign data

The extension's SIMS matching only works inside the zip codes already bundled with it (see the welcome page for the exact list). Extending coverage to more zip codes means pulling fresh records from NYC's public Open Data portal and regenerating signs_data.json.

This queries data.cityofnewyork.us directly -- it's a public dataset, no login, no API key, no private Cyclomedia or SIMS credentials involved.
Requires Python. This is a developer-facing capability, not something to run from the extension itself. If you don't have Python set up, ask the project maintainer to run this for you instead of installing it just for this.

What you need

  • Python 3
  • The packages pandas, pgeocode, requests, pyproj installed (already covered by requirements.txt if you're using the developer/partner package)

Easiest way: the .bat script

From the folder containing pull_more_sims_data.bat, run: 

pull_more_sims_data.bat 10001 10003

Pass every zip code you want covered, not just a new one -- this always rebuilds signs_data.json from scratch for exactly the zip codes given, it does not merge with whatever's there already. If you're adding zip 10002 to the existing bundled area, include all of the existing zips too, not just 10002.

Manual steps (what the .bat script does)

  1. python 01_query_sims_by_zip.py <ZIP> [ZIP ...] -- queries NYC Open Data's Street Sign Work Orders dataset for each zip code (a 1-mile radius around its centroid) and saves the results to a CSV.
  2. python 02_generate_signs_data.py <ZIP> [ZIP ...] -- converts that CSV into signs_data.json, overwriting the extension's bundled data.

After regenerating

  1. Reload the extension in chrome://extensions, then refresh any open Street Smart/Maps tabs.
  2. If you're rebuilding a shareable package, update EXPECTED_ZIPS in build_extension_package.py to match the new zip list -- the build script hard-fails on a mismatch, by design, so a stale package can't ship silently.
  3. Consider regenerating the coverage-area shapefile too (see the welcome page's data-extent section), so it still matches what's actually bundled: 
    python build_sims_data_hull.py path\to\extension\signs_data.json
    Passing the path explicitly avoids guessing at where extension/ sits relative to this script in your particular copy of the project.
